# Visitor analytics and diagnostic test

The website sends page, navigation, conversion, error and heartbeat events from every browser unless that browser opts out on `/privacy`. There is no public consent banner or persistent analytics cookie for ordinary traffic. The server uses the request IP transiently for rate limiting and an approximate unique-visitor sketch, then stores daily and five-minute aggregates. Ordinary events have no visitor ID or individual history. The private Discord webhook reports page, device and time, without an IP or visitor ID.

The administrator dashboard is `/dashboard/visitors`. Its unique, live and visit counts are estimates derived from hashed IPs, so several people behind one public IP may count as one. Day boundaries use UK time. Page paths exclude query strings. Country comes from Vercel's coarse country header. The dashboard's recent list contains only explicit diagnostic tests. Vercel Web Analytics is enabled unless the browser opts out.

The separate diagnostic test is started by a signed-in founder on that browser. It lasts 24 hours and records that browser's public IP, approximate network/location intelligence, browser details and event history. The dashboard shows a one-time, ten-minute claim code. An allowlisted Discord administrator must run `/visitor claim <code>` before `/visitor info`, `/visitor network` and `/visitor myip` can return diagnostic IP data. The test can be deleted early from the dashboard or by opting out on `/privacy`. IP intelligence is an estimate and cannot determine a physical address or reveal an IP hidden by a VPN.

Firestore server collections are `visitorDaily`, `visitorLive`, `visitorRateLimits`, `visitorSessions`, `visitorDiagnostics`, `visitorClaims`, and `visitorAudit`. Browser clients are denied direct access in `firestore.rules`. Aggregate daily rows expire after 90 days; live rows and diagnostic records after 24 hours; claim codes after 10 minutes; audit rows after 90 days. The server checks diagnostic expiry on read. Configure Firestore TTL on `expiresAt` for all seven collections; the daily `/api/visitor-prune` cron also removes expired data. Firestore collections appear on first write. Deploy the changed rules and indexes with `firebase deploy --only firestore:rules,firestore:indexes`.

Set these server-only Vercel environment variables: `FIREBASE_SERVICE_ACCOUNT_JSON`, `VISITOR_BOT_SECRET`, `DISCORD_ADMIN_IDS`, `VISITOR_RATE_SALT`, and `CRON_SECRET`. Optional: `VISITOR_DISCORD_WEBHOOK_URL` for private page notifications and `PROXYCHECK_API_KEY` for diagnostic network intelligence. The bot uses the same `VISITOR_BOT_SECRET` and administrator IDs. Keep all secrets out of `VITE_` variables. The Discord client secret is not needed for this claim-code flow. The IP intelligence provider is [proxycheck.io](https://proxycheck.io/api/); requests are made only for diagnostic tests with provider detection logging disabled.

Run `npm run test:visitor` and `npm run build` at the project root and `npm test` in `discord-bot`. Then configure environment, rules, indexes and TTL in a preview environment and test with your own browser. The bot needs a running Node host and the deployed `/api/visitor-admin` endpoint. Production deployment is a separate step.
